You do not need to learn a new CRM. The useful changes are mostly small quality-of-life improvements: smoother tables, better search, stronger assistant behavior, cleaner workflows, and more stable email/calendar activity.

Why we publish these notes at all: the platform gets improved continuously, and most updates should be invisible — things simply feel faster and break less. But a few changes are worth two minutes of your attention, either because a label changed, because something you share with clients looks different, or because a capability you asked for quietly arrived. This page is that two minutes for June.

## What You Should Notice

### "Deals" Now Read "Opportunities"

The label on deal records was aligned with the word everyone actually uses: **Opportunities** — same as the legacy system everyone came from. Navigation, record pages, and search results all show the new label. Nothing else changed: the records, fields, views, and history are identical, and every saved view still works. If you see an older saved view still named with "Deals," it points at the same records — only the object label was updated.

### Client Pages Look Like ANC Pages Now

Client-facing Pages now use ANC branding consistently. The page header shows ANC on the left and the client/account identity on the right. If a client logo is stored on the Page, it can render there; if not, the Page shows clean initials based on the account name.

What this means for users:

- Client-safe public Pages have a polished ANC look.
- Restricted Pages still require the right access link.
- Draft Pages do not accidentally publish.
- Copy Link still works.
- Sections still expand and collapse.
- Mobile viewing has been checked.

This is worth caring about because Pages travel outside the building — a shared proposal or account page might be the most-seen ANC surface a client touches between meetings. Open one of yours on your phone before sending it; that's the view the client is most likely to have.

### The ANC Guide Is Back On The Side

The in-CRM guide launcher now sits as a side rail beside the app instead of a bottom floating widget. Click **Guide** to open the full visual guide.

<Shot src="/img/screenshots/crm/openanc-guide-side-rail.png" caption="The in-CRM guide now sits on the side rail, so users can open help without covering the working area." />

### Search and Lists Should Feel Cleaner

Saved views, filters, record tables, and search received improvements. For ANC, this matters because most day-to-day work happens in filtered views like proposal pipeline, active opportunities, account lists, and dashboard drilldowns.

Users should still open the same pages, but lists should feel less fragile when filtering, sorting, or moving columns. Searching by opportunity number (for example a deal referenced as `107607` in an email) continues to work alongside name search — if you haven't built that habit yet, [Finding Anything Fast](/docs/training/core/finding-anything) covers it.

The update includes assistant reliability improvements. This should help Scout with reporting and operational tasks.

### Workflows Get Stronger

Workflow improvements give the operations team more room to build clean automations later without changing how users work.

Examples this can support:

- routing new deals
- renewal reminders
- closed-won digests
- load-balanced assignments
- intake follow-up

If one of those sounds like something your team needs, that's a Bucket 2 ask — see [What's Possible](/docs/training/core/whats-possible) for how to raise it well.

### Email and Calendar Activity Should Be Better

For users, the goal is simple: account and opportunity pages should show more useful activity context with fewer sync surprises.

## What The Team Checks

Before changes are announced as ready, the team checks:

1. Login
2. Search
3. Company, Person, and Opportunity pages
4. Saved views
5. Dashboards
6. File previews
7. Mobile loading
8. Scout answers
9. App widgets and command actions
10. Email and calendar activity

That list is why "what's new" notes stay short: the update is verified against the real daily surfaces before anyone is told about it. Your job after an update is small — run your own two-minute version of the same check on the views and pages *you* rely on.

## If Something Looks Wrong

<Callout type="warn" title="Report it with the specifics">
If a view, page, or assistant answer misbehaves after an update, don't work around it silently — report it with the record link, what you expected, and what you saw. One good report gets an issue fixed for everyone; a quiet workaround leaves it broken for the next person. And remember the standing rule: if a *number* looks wrong, check the source records first — data issues and platform issues look identical until you open the record.
</Callout>

## Client Page Ideas Being Considered

These are not all live yet. They are the next client-experience layer the team is evaluating for Pages:

1. Approval buttons for creative, proposals, and requested changes.
2. Section-level comments so client questions stay on the Page.
3. Download blocks for spec sheets, proposal workbooks, and case studies.
4. View analytics for sales follow-up.
5. Proposal expiry countdowns.
6. Side-by-side option comparisons.
7. Project progress trackers.
8. Real-time viewing signals after privacy and logging rules are defined.

If one of these would change how you work with clients, say so — the order this list gets built in is driven by who asks for what, with which account in hand.
